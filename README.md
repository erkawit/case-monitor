# ระบบติดตามระยะเวลาคดี (Case Monitoring Dashboard)

Dashboard ติดตามระยะเวลาคดีจากไฟล์ Excel ของศาล — ประเมินเกณฑ์เฝ้าระวัง (สีเขียว) / เกินกำหนด (สีแดง)
พร้อมรายงานหมายระหว่างพิจารณา (อาญา), การแจ้งเตือนรายวัน และการบันทึกของเจ้าหน้าที่

**สถาปัตยกรรม (Vercel)**

| ส่วน | เทคโนโลยี |
|---|---|
| หน้าเว็บ | HTML + TailwindCSS + DataTables + SweetAlert2 + SheetJS (static) |
| อ่าน/ประมวลผล Excel | ทำใน **เบราว์เซอร์** — ไฟล์ Excel ไม่ถูกส่งหรือจัดเก็บบนเซิร์ฟเวอร์ |
| API | Vercel Functions (Node.js) ใน `api/` — ไม่มี dependency ต้องติดตั้ง |
| ฐานข้อมูล | Upstash Redis (ผ่าน Vercel Marketplace) |
| การเข้าใช้งาน | รหัสผ่าน (`APP_PASSWORD`) + คุกกี้ HttpOnly ลงลายมือชื่อ |

---

## ติดตั้งบน Vercel (ครั้งแรก)

1. **Import โปรเจกต์** — Vercel Dashboard → *Add New… → Project* → เลือก repo `erkawit/case-monitor` → *Import*
   - Framework Preset: **Other** · Build Command: เว้นว่าง · Output Directory: เว้นว่าง
2. **เชื่อมฐานข้อมูล** — เข้าโปรเจกต์ → แท็บ *Storage* → *Create Database* → เลือก **Upstash for Redis** (แผน Free ได้)
   - Region แนะนำ **Singapore (ap-southeast-1)** ให้ใกล้กับ Function (`sin1`)
   - กด *Connect Project* → ระบบจะเพิ่มตัวแปร `KV_REST_API_URL` และ `KV_REST_API_TOKEN` ให้อัตโนมัติ
3. **ตั้งรหัสผ่าน** — *Settings → Environment Variables* → เพิ่ม `APP_PASSWORD` (Production + Preview) ตั้งให้ยาวและเดายาก
4. **Deploy ใหม่** — *Deployments* → เมนู ⋯ ของรายการล่าสุด → *Redeploy* (ตัวแปรใหม่จะมีผลหลัง Redeploy)
5. เปิด URL ของโปรเจกต์ → เข้าสู่ระบบด้วย `APP_PASSWORD` → นำเข้าไฟล์ Excel

หลังจากนี้ทุกครั้งที่ push ขึ้น `main` Vercel จะ deploy ให้อัตโนมัติ
หากเปิดเว็บแล้วขึ้น "ระบบยังตั้งค่าไม่ครบ" ให้ตรวจข้อ 2–4

### Environment Variables

| ตัวแปร | จำเป็น | คำอธิบาย |
|---|---|---|
| `APP_PASSWORD` | ✔ | รหัสผ่านเข้าระบบ (เปลี่ยนรหัส = ทุกคนต้องเข้าสู่ระบบใหม่) |
| `KV_REST_API_URL` / `KV_REST_API_TOKEN` | ✔ | ได้อัตโนมัติจาก Upstash (หรือใช้ `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN`) |
| `AUTH_SECRET` | – | คีย์ลงลายมือชื่อคุกกี้ (ถ้าไม่ตั้งจะสร้างจาก `APP_PASSWORD`) |
| `SESSION_HOURS` | – | อายุการเข้าสู่ระบบ (ชั่วโมง) ค่าเริ่มต้น 12 |
| `CM_KEY_PREFIX` | – | คำนำหน้าคีย์ใน Redis ค่าเริ่มต้น `cm:` (ใช้เมื่อแชร์ฐานข้อมูลกับระบบอื่น) |

## ฟังก์ชันของระบบ

- **นำเข้า Excel** (.xls/.xlsx หลายไฟล์) — แสดงรายการ ลบบางไฟล์/ทั้งหมด → ยืนยัน → Progress 9 ขั้นตอน ล็อกทั้งระบบ ห้ามปิดหน้าต่าง
- **ตรวจหัวตารางอัตโนมัติ** ทุกชีต, รวมคดีซ้ำ (เลขคดีดำเดียวกัน), อ้างอิงวันที่รับฟ้องข้ามไฟล์
- **เกณฑ์อัตโนมัติตามอักษรย่อ**
  - คดีจัดการพิเศษ 5–6 เดือน: ผบ, ผบE, ม, มE, มย, มยE · พ/พE ไม่มีจำเลย หรือข้อหาจัดการมรดก · รส ไม่มีจำเลย
  - คดีจัดการทั่วไป 11–12 เดือน: อ, ย, ยฝ, ฝ · พ/พE มีจำเลย (ข้อหาอื่น) · รส มีจำเลย
  - อักษรย่ออื่น: 11–12 เดือน — ทั่วไป/อื่น ๆ พิจารณาวันนัดต่อไปประกอบ
  - มีเลขคดีแดง = เสร็จสิ้น (ยังแสดงวันนัดต่อไป)
- **ปรับเกณฑ์รายคดี** (ปุ่มซ้ายสุด): 5–6 เดือน / 11–12 เดือน / เกิน 1 ปี แต่ไม่เกิน 1 ปี 6 เดือน
- **หน้าแสดงผลเริ่มต้น** เฉพาะรายการที่ไฮไลต์ (ปุ่ม "แสดงผลทั้งหมด"), ระยะเวลาเหลือก่อนครบกำหนด ณ วันที่เปิดดู
- **หมายระหว่างพิจารณา (อาญา)**: ไฟล์ที่มีคอลัมน์ "วันเดือนปีที่ออกหมาย" — เทียบวันรับฟ้อง → วันออกหมาย กรอบ 5–6 เดือน,
  แยกตาราง "กำหนดโทษว่าง" ไว้ด้านบน, ติ๊ก "ไม่อยู่ในเกณฑ์" (แยกตารางด้านล่าง), บันทึก "ปล่อยชั่วคราว"
- **แจ้งเตือนรายวัน** ใกล้เกินกำหนด (≤ 1 เดือน) และเกินกำหนด — ติ๊ก "ไม่ต้องแจ้งเตือนอีกวันนี้" (จำในเบราว์เซอร์), ปุ่มกระดิ่ง
- **ส่งออก Excel / พิมพ์รายงาน** ตามตัวกรอง
- การบันทึกของเจ้าหน้าที่ (ปรับเกณฑ์ / ปล่อยชั่วคราว / ไม่อยู่ในเกณฑ์) **คงอยู่แม้นำเข้าไฟล์ชุดใหม่**

แก้ไขเกณฑ์ (อักษรย่อ / กรอบเวลา / คำข้อหามรดก) ได้ที่ `RULES` ด้านบนของ `assets/js/processor.js`

## โครงสร้าง

```
index.html               หน้าเว็บ (Navbar, หน้าเข้าสู่ระบบ, Dashboard)
assets/js/processor.js   แกนประมวลผลเกณฑ์ (อ่านชีต, จัดประเภท, คำนวณสถานะ)
assets/js/app.js         ส่วนติดต่อผู้ใช้ + เรียก API
assets/css/app.css       สไตล์ / สีไฮไลต์
api/auth.js              เข้าสู่ระบบ / ออกจากระบบ / ตรวจการตั้งค่า
api/data.js              บันทึก/อ่านผลประมวลผล (gzip-base64)
api/store.js             การบันทึกของเจ้าหน้าที่ (writ_flags / case_rules / writ_exclude)
api/_lib.js              Redis REST, คุกกี้, ตรวจสิทธิ์ (ไม่ใช่ endpoint)
scripts/dev-server.js    เซิร์ฟเวอร์ทดสอบบนเครื่อง
vercel.json              Region sin1, Security headers (CSP, noindex)
```

**ข้อมูลใน Redis**: `cm:data` (ผลประมวลผลบีบอัด), `cm:data:meta`, `cm:store:<ชื่อ>` (Hash), `cm:login:<ip>` (จำกัดการเดารหัสผ่าน 10 ครั้ง/15 นาที)

## ขีดจำกัดที่ควรทราบ

- ผลประมวลผลหลังบีบอัดต้องไม่เกิน ~4.3 MB (ขีดจำกัด request ของ Vercel Functions 4.5 MB) — ข้อมูล 7 ไฟล์ ~1,700 คดี ใช้เพียง ~0.3 MB
- Upstash แผน Free: 500,000 คำสั่ง/เดือน, ข้อมูลรวม 250 MB — การใช้งานปกติของระบบใช้น้อยมาก
- ต้องใช้เบราว์เซอร์รุ่นปัจจุบัน (Chrome / Edge / Firefox / Safari 16.4+) ที่รองรับ CompressionStream

## ทดสอบบนเครื่อง

```bash
npm run dev            # http://localhost:3000  รหัสผ่านทดสอบ: dev  (เก็บข้อมูลในโฟลเดอร์ .data/)
APP_PASSWORD=xxx KV_REST_API_URL=... KV_REST_API_TOKEN=... npm run dev   # ทดสอบกับ Upstash จริง
```
